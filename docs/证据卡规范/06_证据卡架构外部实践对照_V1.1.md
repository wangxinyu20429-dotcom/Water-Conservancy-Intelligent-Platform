# 证据卡架构外部实践对照 V1.1

2026-09-04。本对照用于回答“证据卡应保留哪些承重信息”，不把外部报告规范直接复制成水利科研质量评分。以下分别列出外部事实、可借鉴原则、Codex 推断和本项目选择。

## 一、外部事实与本项目选择

| 外部实践事实 | 可借鉴原则 | Codex 推断 | 本项目选择 |
| --- | --- | --- | --- |
| [Cochrane Handbook 第5章](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-05)说明，系统综述结论取决于收集和分析哪些数据；应收集研究设计、偏倚和结果信息，且数据要准确、完整并可供更新。 | 先围绕研究问题定义需要的数据；设计特征、结果和偏倚信息必须能共同解释结论。 | 证据卡不能只有结论和引用，也不能无边界地收集所有字段。 | 以“当前问题—证据生成机制—决定性 Cxx—有效性边界”为主链，只展开影响判断的设计信息。 |
| [PRISMA 2020](https://www.prisma-statement.org/prisma-2020-checklist)为系统综述提供项目和子项目组成的报告清单；[STROBE](https://www.equator-network.org/reporting-guidelines/strobe/)强调透明报告观测研究，并明确报告指南不是研究质量评价工具。 | 报告完整性帮助发现缺失，但不能代替偏倚判断和科学评价。 | 用“填满多少项”评价证据卡会把报告质量误写成证据强度。 | 不设总分；缺失报告单独记录，结论仍由设计、证据、边界和当前用途决定。 |
| [TRIPOD+AI](https://www.equator-network.org/reporting-guidelines/tripod-statement/)针对回归和机器学习预测模型的开发与验证提供透明报告指南。 | 预测问题必须区分模型开发、验证、数据和性能报告。 | 水利机器学习证据卡必须显式检查独立单位、数据切分、调参、最终测试、信息泄漏和目标分布。 | 原创研究模板增加预测研究分支，但不把临床报告清单原样移植成水利质量标准。 |
| [FAIR 原则](https://doi.org/10.1038/sdata.2016.18)要求数字研究对象可发现、可访问、可互操作、可复用，并强调持久标识、丰富元数据、许可、来源谱系和领域标准。 | 数据和软件需要持久身份、版本、来源链、许可和语义。 | 可发现和可访问不等于数据正确，更不等于适合当前流域任务。 | 数据卡分开记录存在、访问、质量、许可和适用性；每项可以有不同结论。 |
| [USGS 科学数据发布要求](https://www.usgs.gov/data-management/data-release)要求数据、元数据、DOI、审查和可接受仓库等要素，并指出审查要使数据对创建目的而言有完整性、一致性、准确性和所需精度。[USGS 修订指南](https://www.usgs.gov/office-of-science-quality-and-integrity/guidance-documenting-revisions-usgs-scientific-digital-data)要求保存旧版本的来源谱系，因为旧版可能已经支撑论文或政策判断。 | 数据质量必须联系预定用途；版本变化可能改变既有结论，旧版本不能被当前网页静默覆盖。 | 单写产品名或最新版本不足以复查论文使用的数据。 | 数据卡记录产品、处理流、数据截点、接口和许可证组成的版本束，并设置换版重查触发。 |
| [AGU 数据与软件指南](https://www.agu.org/publications/authors/journals/data-software-for-authors)要求支撑研究的数据和软件进入可信仓库，提供可用性声明、持久标识、版本、访问条件和许可，并分别引用论文与制品。 | 论文、数据、软件和活仓库是相互关联但身份独立的研究对象。 | 当前 GitHub HEAD 不能自动代表论文版本；代码开放也不能证明论文结果已复现。 | 软件卡固定 release／tag／commit／容器或权重，并把发现、安装、测试、运行、复现和独立验证分成不同状态。 |

## 二、没有直接照搬的内容

1. PRISMA、STROBE 和 TRIPOD 主要服务报告透明性。本项目把它们当作“可能缺什么”的提示，不把清单完成度当作研究质量或证据等级。
2. FAIR 解决研究对象的发现、访问、互操作和复用。本项目另设任务适用性检验，因为 FAIR 本身不证明误差可接受或适合当前水利问题。
3. USGS 和 AGU 的规则带有机构与出版场景。本项目借用持久身份、版本、审查、来源谱系和可用性原则，不宣称模板等同于其正式合规流程。
4. 不同研究设计需要不同偏倚或验证方法。本项目不建立跨类型总评分，只要求把会改变当前结论的有效性威胁写清。

## 三、对架构的实际修订

本次对照后，V1.1 作出以下选择：

- 从“公共字段＋大量类型字段”改为一条证据主链；
- 每卡先绑定当前问题和预定决定；
- Cxx 成为主题和后续判断引用的最小单元；
- 原创研究保留八部分，但把数据、方法、结果和边界围绕推断目标组织；
- 非论文来源按具体声明和来源组件记录，不套论文结构；
- 明确推断类型，避免描述、关联、因果、预测、规范和实现相互升级；
- 分开作者／发布方解释和本方判断；
- 主动记录失败情景、内部冲突、来源依赖和版本漂移；
- 用用途结论代替总分；
- 用三门判定和最小证据路径控制补读；
- 自动校验只检查结构，不声称科学正确。

## 四、仍需真实样本回答的问题

外部实践只能支持设计方向，不能证明本模板已经适合全部水利科研。仍需通过差异化真实样本检查：

- Cxx 是否能承载复杂图表和多尺度结果；
- 模板是否能暴露水文时空依赖、信息泄漏和外推错误；
- 工程报告的证据层是否足以区分设计值、验收值和长期运行；
- 数据版本束是否能被不同发布平台稳定记录；
- 软件状态分层能否阻止“可运行＝已复现＝科学有效”的误写；
- 三分钟层是否能在不丢关键边界的前提下支持导师判断。
