# 科研证据卡架构 V1.1

证据卡不是文献摘要，也不是字段齐全的读书笔记。它的任务是保存一条可复查的科研判断链：

> 当前问题 → 证据怎样产生 → 决定性证据是什么 → 可作何种推断 → 在什么边界内成立 → 能支持与不能支持什么 → 对当前研究决策有何影响

任何不能帮助核对这条链的信息，不因“看起来完整”而强制填写。

## 一、两层阅读

### 1. 三分钟判断层

只回答六件事：

1. 当前要解决的研究或使用问题；
2. 来源在本问题中的证据角色；
3. 不超过三项决定性结果；
4. 不超过两项足以改变结论的边界；
5. 本卡的使用结论；
6. 下一步动作或停止理由。

这一层不允许把作者解释、本方推断或未核材料写成来源事实。

### 2. 完整证据层

完整层负责解释“为什么可以这样判断”。原创研究保持八部分初读骨架；其他来源按其证据生成机制组织，不套论文八部分。完整层必须有至少一个原子声明块 Cxx。

## 二、原子声明块

一个 Cxx 只承载一个可以被原文证实或证伪的命题。每块必须保留：

- 当前问题和声明性质；
- 来源直接报告的事实；
- 产生该事实的数据、试验、条款、记录、图表或代码组件；
- 对象、时空尺度、样本或统计单位、比较条件；
- 数值、单位、分母、效应量和不确定性；不适用时说明原因；
- 精确定位和必要上下文；
- 可作的推断类型；
- 直接支持什么；
- 不能支持什么；
- 作者或发布方解释；
- 本方判断；
- 核查状态、冲突和来源依赖关系。

摘要、主题页和创新候选必须引用 Cxx，不能重新写一套失去边界的结论。

## 三、推断类型

按来源真实设计选择，不得升级：

- 描述：对象在给定时空和口径下是什么；
- 比较：在明确比较条件下有何差异；
- 关联：变量共同变化，但未建立因果；
- 因果：只有设计和识别条件足以支撑时使用；
- 预测：对明确目标、时域、空间和测试分布的预测性能；
- 机制：存在足够理论或实验链条时使用；
- 规范：某机构要求、建议或允许什么；
- 实现：某版本的软件、数据或工程组件具有什么状态；
- 可迁移性：证据能否转到当前流域、尺度、业务或工程条件。

## 四、使用结论

不使用总分或笼统“可信/不可信”。每个关键声明和整卡分别给出用途结论：

- 可直接使用：原始位置、版本、范围和推断与当前问题匹配；
- 限条件使用：有明确价值，但必须携带限定条件；
- 仅作线索：只能帮助定位原始来源或下一步核验；
- 暂不可用：身份、材料、版本、方法或冲突尚不足；
- 与当前问题无关：来源可有效，但不回答本轮问题。

使用结论必须同时写明“用于什么”“不能用于什么”和“影响哪个研究对象”。

## 五、类型专属核心

| 类型 | 决定解释的核心 |
| --- | --- |
| 原创研究 | 研究问题、推断目标、独立单位、数据与信息流、比较和验证设计、决定性结果、失败情景、有效性威胁 |
| 综述与证据综合 | 检索宇宙、纳排过程、证据单位、偏倚评估、综合模型、异质性、研究重叠、确定性 |
| 调查监测与统计报告 | 目标总体、覆盖框、测量与口径、缺失和非响应、权重校准、估计量、不确定性、修订和可比性 |
| 工程项目报告 | 工程阶段、证据层级、边界条件、基础资料、计算或试验、验收判据、实测与模拟区分、运行失败 |
| 图书与章节 | 命题或定义、论证或推导、原始来源谱系、版本与学派、适用域、例题和经验材料的证据等级 |
| 标准指南与政策 | 发布主体、效力、适用范围、生效版本、规范词、条款、例外、测量与符合性证据、制定依据 |
| 数据集与数据产品 | 数据生成过程、覆盖和变量语义、处理与质量控制、误差和缺失、版本束、许可、任务适用性 |
| 软件模型与代码 | 制品版本、科学模型与实现关系、输入输出和假设、验证与确认、运行证据、论文版本与当前版本、许可依赖 |

## 六、有效性审查

有效性审查不要求每卡写满一套通用清单。只写会改变当前结论的威胁，并区分：

- 来源已经报告的限制；
- 从设计、数据或版本关系可直接看出的限制；
- 本方尚待验证的怀疑。

没有检查到的内容写清“未检查”，不能因模板没有发现问题而判断不存在问题。

## 七、补读资格门

只有以下三项同时成立才打开动态精读、附件、代码或额外来源：

1. 有一个会影响主题、机会、方法、数据或工程决策的明确问题；
2. 当前材料存在一个可定位的决定性证据缺口；
3. 新材料有现实可能改变判断。

触发后只走最小证据路径，达到预先写明的停止条件即停止；允许以“仍不足”结束。

## 八、结构检查的边界

自动检查只能确认身份字段、必要章节、Cxx 声明块、定位和未清占位符是否存在。它不能确认来源是否真实、数值是否抄对、方法是否有效、推断是否成立或导师是否应采纳。
